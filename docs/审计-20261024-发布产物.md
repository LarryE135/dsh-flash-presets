# 发布产物审计（2026-10-24 · 第四轮）

0.2.3 发出去之后，把 **npm tarball 和仓库 HEAD 逐文件比对**，并尝试在解包目录里跑包内自带的自检。

## 结果：发现两个打包遗漏

| # | 发现 | 影响 |
|---|---|---|
| 1 | tarball 里没有 `presets/legacy-0.1.5/` | README 承诺的「DSH 0.1.7 以前的目录式回退（仅 v1）」在 npm 渠道**根本不存在**，`install.sh` 的老路径拿不到文件 |
| 2 | tarball 里没有 `.gitattributes` | 包内自带的 `scripts/verify-presets.mjs` 靠它判断行尾，从 npm 包解包后跑自检 **3 项失败** |

两者的根因都是 `package.json` 的 `files` 白名单只列了三个 `*.patch.yml`，没列 `presets/legacy-0.1.5/` 和 `.gitattributes`。

## 已核对一致的部分

| 文件 | 结果 |
|---|---|
| `presets/flash-lean-ptc-v{1,3}.patch.yml` | md5 与仓库一致 |
| `cordis.patch.yml` | 一致 |
| `scripts/lint-presets.mjs`、`verify-runtime.mjs`、`lint-allowlist.json` | 一致 |
| `README.md`、`docs/CHANGELOG.md` | 一致 |
| 0.2.3 的规则修复（`$env:TEMP`、去掉自相矛盾） | 确认在发布版里 |

## 修复（0.2.4）

`files` 补两项：`presets/legacy-0.1.5/`、`.gitattributes`。实测：

```
npm pack → 解包 → node scripts/verify-presets.mjs --repo-only
文件数 35，校验通过：预设结构与跨平台检查全部通过
```

## 有意不进的（不是遗漏）

| 项 | 原因 |
|---|---|
| `CONTRIBUTING.md`、`.github/` | 面向仓库协作者，npm 用户用不到 |
| `candidates/`、`plugins/`、`marketplace/` | 实验资产与市场材料，不属于发布内容 |

## 教训

「仓库自检全绿」不等于「发布包自检全绿」——自检脚本读的是仓库里的文件，而 `files` 白名单会剪掉一部分。**发布后应该在解包目录里跑一次自检**，这条已写进本轮结论，但还没自动化（可作为下一轮的 CI 步骤）。
