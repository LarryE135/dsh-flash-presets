## 用法

```bash
python3 scripts/apply-pruner-spill.py            # 只看状态（默认动作，不改任何文件）
```

## 触发面实测（很窄，这是关键结论）

| 路径 | 是否会撞上 pruner |
| --- | --- |
| `read` 大文件 | **不会**——返回结构化块（`lines: [{number,text}]`），`measureContent` 只统计 `type:"text"`，按 0 字符计 |
| `bash` 大输出 | **基本不会**——工具自身先截到 ~8 KB（字节），折成字符常低于 8192 阈值 |
| `web_fetch` 长页面 | 会（纯文本） |
| 子代理长回文 | 会（纯文本） |

另：web profile 顶层该条目当前是 `disabled: true`，需 preset 生效才会启用。

## 补丁行为（启用后）

1. 裁剪前拼出将被裁掉的中段；
2. 写 `$DSH_HOME/spill/pruned/<ISO>-<rand>.txt`；
3. marker 变 `[... <N> chars pruned; full output: <path> ]`；
4. 落盘失败或 marker 比被裁内容更长 → 退回原 marker。

单元验证（启用时测得）：20 727 字符 → 裁后 **1 645**，落盘 **19 191** 字符完整可取回。

## 判断

补丁本身正确，但**触发概率极低**、且缺乏零影响证明，所以定位为"可选实验补丁"。
真要常态化收益，应该动的是 bash 的分页提示与 `web_fetch` 的截断策略，而不是 pruner。
