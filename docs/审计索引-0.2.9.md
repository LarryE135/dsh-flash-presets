## 2. 不可协商的契约（审这几条就够了）

1. **id 冻结**：任何发布过的 preset id 不删除、不改名。要改行为就改规则文本、显示名、`description`。
   触发过事故：0.2.7 把 `flash-lean-ptc-v3` 改名 `-lite`，DSH 把 id 持久化在会话日志里，旧会话直接 `agent-preset/not-found`。
2. **发行包只发 2 张卡**：正式发布的 `flash-lean-ptc-v3`（lean-v3）与新增 `flash-lean-ptc-v3-balance`。别的 id 一律不随包。
3. **规则相同的历史 id 只用别名**：`flash-lean`、`flash-lean-ptc`、`flash-lean-ptc-v3-lite` → `flash-lean-ptc-v3`（`presets/legacy-preset-map.json`，运行时内存映射，不写任何文件）。
4. **规则不同的历史 id 既不映射也不随包**：`flash-lean-ptc-v1`、`-v2` 在 `presets/compat-exceptions.json` 里登记 `reason` + `fallback`；`check-preset-compat` 从 git tag 抓历史 id，缺定义又没例外就 `exit 1`。
5. **安装流程不碰会话**：两个安装器与插件启动都不扫描/不改写 `sessions/`。唯一会写会话的是 `plugins/plan-mode-ui/lib/compat-heal.js`，默认关闭（`DSH_FLASH_PRESETS_HEAL=1` 才开），且只改 header、tmp+rename、写前后各校验一次。
6. **别名层只拦解析失败**：`preset-alias.js` patch 了 `resolve/retain/acquireScope/mount/select` 五个入口，纯内存、零写操作、不新增 picker 卡片。

## 7. 刻意为之，不要当 bug 报

1. **仓库里没有 v1/v2 的 patch 文件**：它们在 `compat-exceptions.json` 里，而不是失踪。
2. **本机 roster 有 5 张卡**：多出的 3 张来自 profile 补丁手工追加的行（`v2`/`v3b`/`v3e`），不进发行包。
3. **`publishedVersion` 与 `version` 不一致**（0.2.8 / 0.2.9）：0.2.9 尚未 npm 发布，这是发布流程的中途状态，`lint` 对此有白名单。
4. **`ptc-runtime: persistent-in-memory` 是 profile 级顶层覆盖**：它对 profile 内所有预设生效（包括别人的卡）。这是 0.2.6 起的既有设计，本版未改。
5. **`header≠有效 preset` 有 207 / 28 例**：会话中途换过预设，按 DSH 语义以最后一条 `agent-preset/selected` 为准，不是损坏。
6. **alias 表里有 `-lite`**：0.2.7–0.2.8 的 id 与 v3 规则逐字相同，映射不改行为；这是唯一被允许的映射形态。
