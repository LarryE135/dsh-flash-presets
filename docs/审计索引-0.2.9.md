## 2. 六条契约（改代码前先读）

1. **id 不搬家**：`flash-lean-ptc-v3` / `-balance` 的 id 与 `config.id` 永远不变；改行为改内容，不改标识符。
2. **历史 id 必须可解析**：定义 / 别名 / 登记例外，三者之一。`node scripts/check-preset-compat.mjs` 强制。
3. **别名层只拦「解析失败」**：包装的是上游 registry 上真实存在的 6 个入口 —— `resolve` / `retain` /
   `acquireScope` / `readDocument`（GUI 的远程名是 `read`）/ `mount` / `select`。前四个先按原 id 调，
   只有 `agent-preset/not-found` 才用 canonical 重试一次；`mount` / `select` 先用 `service.definitions`（上游
   确实是个 Map）确认该 id 到底有没有定义，**有定义就不换**（不许劫持用户自己建的同名预设）。
   上游这 6 个入口全是 async / 返回 Promise 的，包装函数按「同步返回同步、Promise 返回 Promise」处理，
   两种形态都有回归测试。
4. **不写用户数据**：仓库里没有任何代码在安装/启动时改写 `sessions/`；CI 断言装一次 + 卸一次后会话目录校验和不变。
5. **规则变化必须可见**：`rulesDiffer: true` 的别名首次命中打印 `[preset-alias] 注意：…`，并在 `legacy-preset-map.json` 里写明原规则。
6. **fail-closed**：兼容闸门拿不到 git tag → `exit 2`；`publish.sh` 的版本/分支/工作区不一致 → 拒绝发；
   脚本安装遇到已有插件卡 → `exit 4`。宁可停下来，不许假装通过。

## 7. 刻意为之（不是 bug）

- **发行包只有两张卡**：v1/v2 的规则是历史包袱，不占卡片；但它们仍然可解析（别名）。
- **`-lite` 会出现在脚本安装的补丁层里**：这是升级路径的兼容行（`order: 99`，名字标「勿选」），删掉它那些会话就 not-found；
  插件卡路径不需要它（有别名层）。
- **`rulesDiffer` 的别名会改变会话行为**：这是「打得开」换来的，代价写在警告里，用户可以在 profile 补丁里加回原 id。
- **`doctor` 对「历史 id 又有定义」只提示不判失败**：本机就是这样保留 v2 的，不能因为它红。
- **`ptc-runtime: persistent-in-memory` 是 profile 级覆盖**：对这一 profile 的所有预设生效，`--uninstall` 会撤掉。
