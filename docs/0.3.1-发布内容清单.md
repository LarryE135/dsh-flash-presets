## 7. 发布步骤（审计通过后执行）

1. 推送本轮审计与修复提交，等 CI 绿。
2. 临时停用 `freeze released tags` → `git tag -f v0.3.1 <最终提交>` → `git push -f origin v0.3.1` → 立刻恢复并确认 `enforcement=active`。
3. `node scripts/verify-published.mjs --version 0.3.1`（registry 已生效，此步只作复核）。
4. `gh release create v0.3.1 --verify-tag --title "…" --notes-file <(CHANGELOG 0.3.1 段)`。
5. 复查三处一致：`git ls-remote origin refs/tags/v0.3.1` 的 SHA == 本地 HEAD == `npm view dsh-flash-presets@0.3.1 gitHead`。

## 8. 回滚预案

- npm 的 0.3.1 **不可静默替换**：包内容一旦发布就不能改（会破坏 lockfile 校验）。若发现严重问题 → 升 0.3.2 修，并对 0.3.1 打弃用标记：`npm deprecate dsh-flash-presets@0.3.1 "原因 + 请改装 0.3.2"`。
- git tag 若已对齐并发布：不再移动（规则集也会拒），同样走升版本号。
- 用户侧回退：`dsh plugin --profile <p> add dsh-flash-presets@0.3.0`（0.3.0 的插件行与预设都还在）。
