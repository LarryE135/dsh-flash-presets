## 2. 发布前必须做

1. PR 合并且四项必过检查全绿（`verify (ubuntu-24.04)` / `plugin-tests (24)` / `integration` / `pack-doctor`）。
2. 本地 `git switch main && git reset --hard origin/main`，确认 HEAD 就是 main 上的 squash 提交。
3. `npm run verify:full` 13/13；`npm pack --dry-run` 确认文件数（不含 `docs/审计索引.md`）且无本机路径。
4. DSH 0.2.2-rc.1 实机验收：light+auto 下第 2 条消息不弹评审卡；改档位后自动批准仍在；PTC 下评审超 2 分钟不出两张卡；桌面端面板读写正常（不被 Host 白名单误伤）。
5. `git tag -a v0.3.3 -m "0.3.3"`，先 `git merge-base --is-ancestor v0.3.3 origin/main`，再 `git push origin v0.3.3`。

## 3. 发布

1. 等 tag 上的 CI 全绿。
2. `npm whoami` 确认登录后跑 `bash scripts/publish-npm.sh`（新版会自查 publishedVersion、安装器引用、tag 是否在 `origin/main` 上）。
3. `bash scripts/publish.sh` 创建 GitHub Release（脚本会拦直推 main，now 只能走 PR）。
4. 复核：`npm view dsh-flash-presets@0.3.3 gitHead` == `git rev-parse v0.3.3`；Release 附件哈希与 `git archive v0.3.3` 一致；README 徽章可渲染。
5. 在 #29 回复修复版本并关闭；Release 说明里提醒 pnpm 的 24 小时成熟期（当天装裸包名可能仍拿 0.3.1）。
