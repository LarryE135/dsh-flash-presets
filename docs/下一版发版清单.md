## 2. 发布前必须做

1. PR 合并且四项必过检查全绿（`verify (ubuntu-24.04)` / `plugin-tests (24)` / `integration` / `pack-doctor`）。
2. 本地 `git switch main && git reset --hard origin/main`，确认 HEAD 就是 main 上的 squash 提交。
3. `npm run verify:full` 13/13；`npm pack --dry-run` 确认文件数（不含 `docs/审计索引.md`）且无本机路径。
4. `git tag -a v<新版本> -m "<新版本>"`，先 `git merge-base --is-ancestor v<新版本> origin/main`，再 `git push origin v<新版本>`。

## 3. 发布

1. 等 tag 上的 CI 全绿。
2. `npm whoami` 确认登录后跑 `bash scripts/publish-npm.sh`（会自查 publishedVersion、安装器引用、tag 是否在 `origin/main` 上）。
3. `bash scripts/publish.sh` 创建 GitHub Release（脚本会拦直推 main，只能走 PR）。
4. 复核：`npm view dsh-flash-presets@<新版本> gitHead` == `git rev-parse v<新版本>`；Release 附件哈希与 `git archive v<新版本>` 一致；README 徽章可渲染。
5. 在 #29 回复修复版本并关闭；Release 说明里提醒 pnpm 的 24 小时成熟期（当天装裸包名可能仍拿上一版）。

### 5.2 第四轮新增登记（本轮发现，未修）

- **计划模式判定权威顺序不一致**：`builtinPlanActive` 与 `decidePlanning` 谁是权威没统一（一个投影优先、一个服务优先），两处都可能先说话。
- **评审守卫是静态正则**：先取值再调用（`const f = tools[X]; f({...})`）这类形态覆盖不到 —— 正则能覆盖的边界见 P3-1。
- **`lib/core.js` 取 webServer 的来源顺序仍需真机验证**：宿主「只注册服务」与「只挂属性」两种形态都要实测，现在只按 `ctx.get` 一条路走。
- **状态里 `gateStats` 的 `stateOf` 用了已废弃 API**（同 P3-12 的家族，状态接口这一侧）。
- **PHASE 2 的三个计数只进 debug**：`phase2Sent` / `phase2Failed` / `phase2Dropped` 没进状态页，排障要翻日志。
- **`merge-presets --remove` 遇到用户自己写的流式 YAML 仍会被结构闸拒绝**（按设计如此：不敢猜结构），提示语可以更友好，指向「手工改成块状数组再试」。
