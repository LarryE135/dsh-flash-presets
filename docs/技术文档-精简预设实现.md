# Flash 精简预设：实现方式、路径与技术细节

> 面向要讲清楚它怎么工作。每节自带文件路径与可执行命令，可直接当视频分镜。
> 口径：dsh-flash-presets 0.2.5（已发 GitHub Release），DSH 0.2.1-rc.5 实测。

---

## 0. 一句话定位

它不是代码插件，是一个**组合包（bundle）**：安装时往用户 profile 里插入几条 `@deepseek-ai/dsh-agent-preset` 行，宿主运行时**不加载本包任何代码**。

- 交付形态：`package.json` 的 `dsh.bundle.patch` 指向 `cordis.patch.yml`（一份 YAML 补丁层）
- `lib/index.mjs` 全文只有 `export function apply() {}`——存在的唯一理由是给 npm 包一个合法运行时入口
- 功能全在两层：**预设定义（YAML）** 与 **安装/校验脚本（Node）**

适合当开场：一个 npm 包里没有功能代码，功能是“往别人的配置里写配置”。

## 2. 一个预设是什么

一个预设 = 一条 `@deepseek-ai/dsh-agent-preset` 行 + 它的 `plugins:` 数组：

```yaml
- insert:
    - id: preset-flash-lean-ptc-v3
      name: '@deepseek-ai/dsh-agent-preset'
      config:
        id: flash-lean-ptc-v3          # 界面上看到的标识
        name: "Flash 精简·PTC v3（v4.1-flash）"
        order: 27                       # 预设列表里的排序
        plugins:
          - id: persona
            name: '@deepseek-ai/dsh-persona'
            config:
              prefix: You are a coding agent powered by the {{model}} model.
              suffix: |-                # 13 条硬规则写在这里
                FLASH OPERATING RULES (hard constraints; ...)
          - id: compaction-basic            # 省 token 的主旋钮
            name: '@deepseek-ai/dsh-compaction-basic'
            config: { thresholdRatio: 0.25, retainTokens: 20000 }
```

三个结构性要点：

1. `config.plugins` 是**覆盖层**，不是完整清单：只写要改的、要加的、要停的。
2. 要停一个能力**不删行，写 `disabled: true`**：

```yaml
          - id: tool-workflow
            name: '@deepseek-ai/dsh-tool-workflow'
            disabled: true
```

   这比删行更重要——它的工具 schema 因此**根本不进系统提示**，是零成本收益。
3. `{{...}}` 是**严格插值**：必须是宿主注册过的变量（目前只有 `provider` / `model`）。写别的（比如沿用 Claude Code 的 `{{cwd}}`）会让整轮对话抛 `unknown prompt variable` 并中止。这条坑真踩过，见第 8 节。

## 3. 三个版本的差异

| 项 | v1 | v2 | v3（主推） |
|---|---|---|---|
| order | 21 | 22 | 27 |
| 规则条数 | 14 | 12 | 13 |
| `thresholdRatio` | 0.3 | 0.25 | 0.25 |
| `retainTokens` | 50000 | 20000 | 20000 |
| 旧版目录回退 | 有 | 无 | 无 |
| 定位 | 最全 | 中等 | 精简 + 反过度自测 |

v3 的差别不是“更少”，而是第 4 条规则（**交付前跑一次合并验收，过了就停**），针对的失败模式是“答对了但超时”。

## 4. 合成：源文件 → 出货补丁

```bash
node scripts/compose-bundle-patch.mjs          # 生成 cordis.patch.yml
node scripts/compose-bundle-patch.mjs --check  # 断言合成结果 == 源文件（CI 与 prepublishOnly 都跑）
```

- 合成是**确定性**的，同输入字节一致（实测 md5 相同）
- `--check` 防“改了源文件忘了重新合成”——这种错误在 npm 包里表现为“用户装了旧规则”，文本校验看不出来

## 5. 安装路径：`install.sh` → `merge-presets.mjs`

壳脚本只做三件事：找 `$DSH_HOME`、选 profile、调 `node scripts/merge-presets.mjs`。逻辑全在 174 行的 merge 里：

| 步骤 | 函数 | 干什么 |
|---|---|---|
| 1 | `detectEol(s)`（L38） | 跟随用户已有文件的行尾（CRLF/LF），不硬编码 |
| 2 | `stripBlock(raw)`（L57） | 先摘掉旧托管块，保证重装不叠加 |
| 3 | `adoptForeignRows(text)`（L86） | **认领历史残留**：块外的裸 `- id: preset-flash-lean-ptc-vN` 也摘掉 |
| 4 | `buildBlock(eol)`（L44） | 用解析过平台标签的预设行重建托管块 |
| 5 | 写盘 + 备份 | 先 `.bak-<时间戳>`，再写 |

托管块用一对注释包裹（L19 / L20），边界稳定可搜：

```yaml
# >>> dsh-flash-presets: managed block (0.1.7+ plugin-row presets) >>>
... 预设行 ...
# <<< dsh-flash-presets: managed block <<<
```

**幂等性**是这里最值钱的属性：连装两次 md5 不变、用户自己的行原样保留、托管块恰好一个（selftest 有专门断言）。

**平台标签**：源文件写 `disabled: !!js process.platform === 'win32'`，写盘前由 `lib/platform-tags.mjs` 的 `resolvePlatformTags()`（L26）解析成 true/false。理由很实际：`!!js` 是 DSH include 插件注册的非标准标签，写进用户配置后，任何用标准解析器读它的人（编辑器、CI、别的工具）都会炸。不认识的表达式直接报错，不猜。

## 6. 五个校验器，各守一层

| 校验器 | 守什么 | 抓不到什么 |
|---|---|---|
| `verify-yaml.mjs` | 真 YAML 解析，v1/v2/v3 + **合成产物**都要能解析 | 取值对不对 |
| `verify-presets.mjs` | 取值：order / 规则条数 / 阈值 / `disabled` 行 / 托管块结构 | 文本可移植性 |
| `lint-presets.mjs` | 绝对路径、`/tmp/` 之类平台专属写法、冻结项白名单 | 结构错误 |
| `verify-runtime.mjs` | 真跑 `dsh --dump-config`，断言预设真的进了合成结果 | 交互层行为 |
| `selftest.sh` | 安装/卸载/幂等/CRLF/BOM/中文共 30 项 | 真机 GUI |

为什么需要五个——它们**互相看不见对方的盲区**：

- 文本正则看不出缩进错 → 必须真解析
- 但“源文件和合成结果一起坏”时解析也能过 → 必须加 `--check` 并解析**产物**
- 解析合法不等于“用户装的版本对” → 必须真跑一次 `--dump-config`

## 7. 诊断入口：`doctor.mjs`

```bash
node scripts/doctor.mjs --profile web          # 体检
node scripts/doctor.mjs --profile web --fix    # 就地修（先备份，再解析标签）
node scripts/doctor.mjs --profile web --dump   # 额外验证 dsh 是否认这些预设
```

五项：DSH 版本 ≥ 0.1.7、托管块是否恰好 1 个、块外残留行、`!!js` 行号（**排除注释里的说明文字**）、标准 YAML 能否解析（报错带行号）。

最后一项的价值：把“你的配置有问题”和“配置没问题，问题在别处”分开。

## 8. 两个真实漏网案例

**案例 A（issue #4）**：v3 的 YAML 缩进坏了，`npm run verify` 依然全绿。原因：YAML 校验的 EXPECT 只登记 v1/v2，合成产物没人解析，其余全是文本正则。

**案例 B（issue #5）**：v1/v2 的 persona 写了 `Your working directory is {{cwd}}.`。DSH 插值是严格模式，只注册 provider/model，于是**选中该预设后任何一轮对话直接失败**。发布前全绿，用户侧必炸。

修法都是“把断言下沉到能看见它的那层”：A 补 v3 进 EXPECT + 解析产物 + 安装层三个都查；B 新增“未注册提示词变量”断言，扫描 6 个出货文件的 `{{var}}`，白名单只有 provider/model。

## 9. 出货的两道闸门

| 闸门 | 机制 | 效果 |
|---|---|---|
| npm 包 | `package.json` 的 `files` 是**白名单** | 未列目录不进包（`plugins/` 因此 0 文件） |
| GitHub Release | `.gitattributes` 里 `plugins/ export-ignore` | `git archive` 的 zip 不含 `plugins/`（改前 21 文件） |

发布链：`scripts/publish.sh` 校验 tag → `git archive` 出 `dist/dsh-flash-presets-<tag>.zip` → `gh release create`；`prepublishOnly` 串起全部校验（含 30 项 selftest），过不了不发。

两道必须**分开设**：只写 files 挡不住 git archive，只写 export-ignore 挡不住 npm 包。

## 10. 跨平台：踩出来的四条

1. **ESM 拼路径**：Windows 上 `new URL(import.meta.url).pathname` 得到 `/D:/...`，再 `path.join` 变 `D:\D:\...`。统一用 `fileURLToPath`。
2. **CRLF**：安装器跟随用户文件行尾写块，Windows 下就是 CRLF；断言必须写 `\r?\n`，否则功能正常却报“校验失败”。
3. **bash 3.2 全角字符**：macOS 自带 bash 3.2 解析 `$VAR（` 会把全角并进变量名，配 `set -u` 直接 unbound variable。凡全角紧跟变量一律写 `${VAR}`；`scripts/check-bash32-cjk.mjs` 专扫这个。
4. **PowerShell 5.1 的 BOM**：`.ps1` 带 UTF-8 BOM 才能让 5.1 正确识别中文，selftest 有一条断言 BOM 没被编辑器吃掉。

## 11. 省 token 的三个旋钮

| 旋钮 | 配置 | 效果 |
|---|---|---|
| 压缩点提前 | `compaction-basic: thresholdRatio 0.25 / retainTokens 20000` | 默认 0.8 在该路由（100 万窗口）≈ 80 万才触发，长会话根本碰不到；0.25 让每次会话都真压缩 |
| 工具输出裁剪 | `tool-result-pruner: thresholdChars 8192 / headChars 4096 / tailChars 1024` | 单条结果超 8 KB 只留头 4096 + 尾 1024，中段丢弃 |
| 关插件 | `tool-workflow`、`workflow-ptc`、`tool-ralph`、两个 subagent 工具、`tool-plugin-manager` 共 6 个 | 工具 schema 不进系统提示 |

配套行为规则（v3 第 6/7/8 条）：批量独立调用、长输出重定向到文件、只读新增内容、NOTES ≤ 60 行、不重复输出未改动的文件。
> 四个机制的逐条详解（原理、算例、误伤边界、验证命令）见「技术文档-省token四机制.md」。


**边界要讲清**：压缩与裁剪单向不可逆，被摘要的轮次、被裁的中段都拿不回来；判据全是字符数与比例，没有语义判断，所以“你正需要的那段恰在中段”时会误伤且不报警。

## 12. 已知边界（诚实清单）

1. `install.ps1` 没在真实 Windows + PS 5.1 上跑过（本机无 pwsh，只有静态审查 + CI 三平台）。
2. `publish.sh` / `publish.ps1` 未实测（0.2.5 刚发 GitHub Release）。
3. `verify-yaml` 找不到 js-yaml 时退出码 2（跳过≠通过）；本机因 DSH 全局自带 js-yaml 无法复现该分支。
4. 预设激活的端到端验证缺一跳：headless profile 不含 `agentPresets` 注册表，web 型 profile 不接受 CLI 提示词。
5. `plugins/plan-mode-ui/` 是另一处源的副本，需手动同步。
