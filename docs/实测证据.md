# 实测证据

数据来自 DSH headless + PTC 的批量运行（2026-10）。计费口径为会话事件中 `inputTokens + cacheReadTokens` 的累计和；「比值」指相对官方基准耗时的倍数，越小越好；「满分」指官方样例全部通过。

每组样本量为 2 到 3，结论按方向读。本页记录的是试过什么、哪些没有成立，不是排行榜。

## P15654（19 组官方样例，时限 4 s）

| 配置 | 满分 | 计费（M） | 备注 |
|---|---|---|---|
| v3，原题面 | 1/3 | 3.5 / 10.5 / 12.8 | 两次失败为 4.00 与 4.01 s 超时，峰值 184 MB |
| v3，题面要求留下可复跑的 verify.log 且必须全过 | 3/3 | 合计 17.5 | 两次由第二轮修正，16 到 19、15 到 19 |
| 标准模式（无预设） | 2/2 | 1.9 / 2.2 | 洛谷实测 100 分 |

失败原因不是没写出来，而是停在分档特判、常数卡在时限边界。把验收标准写死后消失，总成本也下降。

## P15114（32 MB 内存陷阱）

| 配置 | 洛谷得分 |
|---|---|
| v3b，旧题面 | 60，峰值 134.41 MB |
| v3b，题面写明 512 / 32 MB 与判分口径 | 100，1.31 s、5.15 MB |
| 标准模式 | 100，4.97 s、4.49 MB |
| v3 | 100，1.88 s、15.22 MB |

该题的唯一实质变量是内存。题面不写限制，模型按 512 MB 设计。

## P2099（提交答案，连续评分）

| 配置 | 比值 |
|---|---|
| 标准模式 | 0.99 / 1.09 / 1.04 / 1.05 |
| v3，只判合法性 | 1.05 到 1.15，低于标准模式 |
| v3，判「合法且比值 ≤1.05」并回灌失败清单 | 1.05 / 1.03 / 0.98 |

连续评分题的验收必须带质量阈值。只判合法性时模型合法即收工。

## 验收契约预处理（2026-10-20，ocgo high 档）

| 臂 | 比值 |
|---|---|
| A 直接开跑 | 1.02 / 0.99 / 1.05，中位 1.02 |
| B 只加载验收契约块 | 1.08 / 1.03 / 1.05，中位 1.05 |
| C 契约加最多 3 个带默认值的提问与答复 | 1.11 / 1.01，中位 1.06 |

契约块本身写得没有问题，第 4 项确实标出了包围口径、连通性、评分目标三个真实歧义，但质量没有提升。因此本仓库没有把难度自评与开工前提问写进预设。

## 受控复现（P15114，headless + PTC，n=2）

| 预设 | 计费（M） | 步数 | 墙钟（s） | 正确 |
|---|---|---|---|---|
| 标准 | 7.03 | 66.5 | 719 | 2/2 |
| v3 | 4.64 | 39.5 | 759 | 2/2 |
| v3b | 5.37 | 47 | 804 | 2/2 |

全部正确时，v3 的计费约为标准模式的 66%，墙钟略长。样本量 2，不构成显著性证据。

## 已撤回的说法

- 「标准模式成本是 v3 的 22 倍」：原始对比混用了 GUI 与 headless，口径不可比，撤回。
- 「v3 会系统性交部分分」：合并 8 次 P15654 后为 3/8 满分，属高方差，不是系统性失败。
