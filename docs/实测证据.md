# 实测证据（2026-10）

所有数字来自 **DSH headless + PTC** 的批量运行；计费口径 = 会话事件里 `inputTokens + cacheReadTokens` 的累计。
同一格内的"比值"指相对官方基准耗时的倍数（越小越好），"满分"指官方样例全过。

> 样本量都很小（每题 n=2~3）。本页的作用是**记录我们试过什么、哪些没成立**，不是排行榜。

## 1. P15654（19 组官方样例，限 4 s）

| 配置 | 满分率 | 计费（M） | 备注 |
|---|---|---|---|
| v3，原题面 | 1/3 | 3.5 / 10.5 / 12.8 | 两次失败为 4.00 / 4.01 s TLE、184 MB |
| v3，题面加"必须留可复跑 verify.log，且必须全过" | **3/3** | 合计 17.5 | 两次靠第二轮救回（16→19、15→19） |
| 标准模式（无预设） | 2/2 | 1.9 / 2.2 | 洛谷实测 AC 100 |

结论：**v3 的失分不是"不会做"，是"停在分档特判 + 常数卡边界"**；把验收标准写死就能修掉，且总成本更低。

## 2. P15114（32 MB 内存陷阱）

| 配置 | 洛谷得分 |
|---|---|
| v3b + 旧题面 | 60（134.41 MB，爆内存） |
| v3b + 写明 512/32 MB 与判分口径 | **100**（1.31 s / 5.15 MB） |
| 标准模式 | 100（4.97 s / 4.49 MB） |
| v3 | 100（1.88 s / 15.22 MB） |

结论：这题唯一实质变量是**内存**；题面不写限制，模型就按 512 MB 设计。

## 3. P2099（提交答案，连续评分）

| 配置 | 比值（中位） |
|---|---|
| 标准模式 | 0.99 / 1.09 / 1.04 / 1.05（中位 ~1.05） |
| v3，只判"合法" | 1.05–1.15（**比标准差**） |
| v3，判"合法且比值 ≤1.05" + 回灌失败清单 | **1.05 / 1.03 / 0.98** |

结论：连续评分题的验收必须带**质量阈值**，只判合法性会让模型合法即收工。

## 4. 验收契约预处理：无效（2026-10-20，ocgo high 档）

| 臂 | 比值 |
|---|---|
| A 直接开跑 | 1.02 / 0.99 / 1.05（中位 1.02） |
| B 只加载"验收契约"块 | 1.08 / 1.03 / 1.05（中位 1.05） |
| C 契约 + 最多 3 个带默认值的提问 + 答复 | 1.11 / 1.01 （中位 1.06） |

契约块本身写得没问题（第 4 项确实标出了"包围口径 / 连通性 / 评分目标"三个真歧义），但**质量没有提升**。
所以本仓库没有把"难度自评 / 开工前提问"写进预设。

## 5. 受控复现（P15114，headless + PTC，n=2）

| 预设 | 计费（M） | 步数 | 墙钟（s） | 正确 |
|---|---|---|---|---|
| 标准 | 7.03 | 66.5 | 719 | 2/2 |
| v3 | 4.64 | 39.5 | 759 | 2/2 |
| v3b | 5.37 | 47 | 804 | 2/2 |

结论：**全对时**，v3 的计费约为标准的 66%，墙钟略长。差异在 n=2 下不构成显著性证据。

## 6. 未能成立的旧说法（已撤回）

- "v3 会系统性交部分分"：合并 8 次 P15654 后为 3/8 满分，属**高方差**，不是系统性失败。
