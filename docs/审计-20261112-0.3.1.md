# 0.3.1 发布前审计（2026-11-12）

> 触发：0.3.1 定版推送后，`npm publish` 报成功、我用两种方式查 registry 都说"没有这一版"，一度判定"发布没落地"并撤掉了 Release。作者指示先不发 Release、回退到仓库状态做审计。
> 范围：发布链路本体（版本号、tag、npm、Release、文档口径）+ 0.3.1 与 0.3.0 的内容差异。产品能力评估不在此（那属于 DSH-Bench）。

## 1. 结论摘要

1. **npm 0.3.1 确实发出来了**：`latest` = 0.3.1，发布时间 `2026-11-12T16:38:36Z`，`gitHead` = `5d02bee`，tarball 42 文件 / 640 KB 解包，带 npm 签名。
2. **我最初的"未发布"结论是取证错误**：① 直接 fetch `registry.npmjs.org` 拿到的是边缘缓存的旧 packument（`time.modified` 停在 11-10）；② `npm view <pkg>@<ver> version --json` 把 `version` 拼进同一个 argv 元素时，npm 会打整份 packument，脚本拿对象比字符串恒不相等。两处陷阱已在 `scripts/verify-published.mjs` 文件头记死。
3. **真问题不是发布，而是流程**：`npm publish` 之后没有任何复核，Release 又建在 npm 之前，tag 与 npm 的 `gitHead` 已经不一致 —— 这三条现在都有守卫或已记入发布步骤。

## 3. P0：取证方法本身不可靠（已修）

同一个事实用两条路查，给出一致的错误答案，这是我这次误判的根因：

| 取法 | 返回值 | 真实情况 |
|---|---|---|
| `urllib` 直连 `/dsh-flash-presets/0.3.1` | 404；包文档 `modified` = 2026-11-10 | 边缘缓存副本，落后约 20 分钟 |
| `npm view pkg@0.3.1 version --json`（字段拼进 spec） | 整份 packument（含 0.3.1），脚本解析成"不匹配" | 参数拼错，等于问"整包" |
| `npm view pkg@0.3.1 version --json`（字段单独 argv） | `"0.3.1"` | 正确 |

**教训**：发布状态只能由 npm CLI 判定；任何自写的 registry 探测都必须走 `npm view`，且字段要单独一个 argv。

**已修**：`scripts/verify-published.mjs` 用正确的 argv 形态轮询 `npm view`，并同时校验 `dist-tags.latest`；文件头把两条陷阱写成注释，避免后人重犯。

## 4. P1：流程缺口

### D1. 发布后没有复核（根因之一）

`npm publish` 打一行 `+ pkg@ver` 就退出 0，之前没有任何一步去看 registry 到底有没有。现在有两条路都带复核：

- `scripts/publish-npm.sh`：干净工作区 → 版本与 README 一致 → tag 在 HEAD → tag 已推远端 → `npm publish` → `verify-published.mjs` 轮询（默认 120 s，失败 exit 1）。
- `scripts/verify-published.mjs --version <v>`：可单独跑，也可在 CI 里跑。

### D2. 顺序反了：Release 早于 npm

先建 Release 会让正文里的安装命令指向一个还装不到的版本。规则改为 **npm → 复核 → Release**，并在 `scripts/publish.sh` 建 Release 之前加硬检查（npm 上查不到该版本就拒绝，除非显式 `ALLOW_MISSING_NPM=1`）。

### D3. `sync-published-version.mjs` 与提示不一致（已修）

旧脚本只改 `publishedVersion`，但 `verify-versions.mjs` 的报错提示说它会同步 marketplace 的 npm 引用 —— 一改就红。现在它真的同步：`publishedVersion` + `marketplace/plugin.json` + `README.md` / `README.en.md` / 两个安装器里的 `dsh-flash-presets@<旧版本>`。

### D4. 文档 lint 认不出"npm 发了、Release 没发"

`lint-presets.mjs` 的规则是"提到当前版本就不能说未发布"，于是"npm 已发、GitHub Release 尚未发布"这种**真话**会被判红。建议把匹配收紧到 `npm` 语境（例如只在同句出现 `npm` 且无 `Release` 时判红）。在这之前，文档统一改用"Release 排在审计之后补"这种表述。

## 7. 发布步骤（审计确认后照此执行）

1. 把本轮审计与修复提交并推 `main`，CI 绿。
2. **对齐 tag**：临时停用 `freeze released tags` → `git tag -f v0.3.1 <最终提交>` → `git push -f origin v0.3.1` → 立刻恢复，并确认 `enforcement=active`。
3. `node scripts/verify-published.mjs --version 0.3.1`：确认 registry 侧 0.3.1 与 `latest` 都对。
4. 建 Release（`gh release create v0.3.1 --verify-tag ...`，正文取 CHANGELOG 0.3.1 段）。
5. 发布后复查：`git ls-remote origin refs/tags/v0.3.1` 的 SHA、`npm view ... gitHead`、Release 附件三者一致。
