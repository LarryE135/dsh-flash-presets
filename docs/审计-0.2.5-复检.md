日期：2026-10-30　　范围：dsh-flash-presets 工作树（未发版，改动并入 0.2.5）

## 一、修的问题

### 1. issue #5：v1 / v2 预设会让整轮对话直接失败

- **现象**：选中 `flash-lean-ptc-v1` 或 `v2`，任意一轮对话抛
  `unknown prompt variable "{{cwd}}" in section "deployment:persona-suffix"` 并中止。
- **根因**：DSH 的提示词插值是严格模式，`{{var}}` 必须是已注册变量，目前只注册 `provider` 与 `model`；
  工作目录走 runtime context，不走占位符。`Your working directory is {{cwd}}.` 是 Claude Code 的写法。
- **修复**：删掉该句（不丢信息——运行时上下文本来就会给出工作目录），四处全改：
  - `presets/flash-lean-ptc-v1.patch.yml`
  - `presets/flash-lean-ptc-v2.patch.yml`
  - `cordis.patch.yml`（重新合成）
  - `presets/legacy-0.1.5/flash-lean-ptc-v1/agent.cordis.yml`（**审计中新发现**：旧版目录式安装同样带这句，v3 之外的出货路径也中招）
- **证明**：用 DSH 自己的 `renderPrompt` 复现故障点——
  修复前的 suffix 抛 `unknown prompt variable "{{cwd}}"...`，修复后的 suffix 正常渲染。

### 2. 新增防线：未注册提示词变量断言

`verify-presets.mjs` 现在扫描 6 个出货文件里的 `{{var}}`，只允许 `provider` / `model`，其余直接判失败。
此前这类错误只在用户选中预设时才炸（发布前全绿，用户侧必炸）。

## 五、给后续的判断口径

- 提示词里的 `{{...}}` 属于**严格插值**，加新的占位符前先确认 DSH 注册了哪些变量；这次已把该约束固化成断言。
- 同一份规则在四处存在（v1/v2/v3 源 + 旧版目录 + 合成产物），改规则要四处同步，`compose` 只覆盖前三处的合成关系，旧版目录靠人工。
