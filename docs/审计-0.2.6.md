`docs/提交清单-规划插件与实验-20261024.md`、`docs/实验记录-计划模式与可验证验收-20261024.md`、`docs/规格-规划插件-v1.md` 都在引用：

处理：全部入库（`6347d57`）。这些不随 npm 包发布（`files` 白名单不含），只作为仓库内实验产物保留。

### P1 · 插件补丁里写死本机绝对路径（已修）

`plugins/plan-scope/bundle.patch.yml` 第 3 行：

    name: "file:///home/larry/Common/dsh-flash-presets/plugins/plan-scope/lib/index.js"

别人拿到这份补丁根本无法加载。改成 `bundle.patch.example.yml`：占位符 `file:///ABS/PATH/TO/...` + 一行生成命令（`node -e "console.log('file://'+require('path').resolve('plugins/plan-scope/lib/index.js'))"`），机器相关文件不入库。

### P2 · 校验器把候选文件一律判成失败（已修）

`verify-yaml.mjs` 的"安装器路径"会硬断言输入文件含 v1/v2/v3 三行。于是：

    $ node scripts/verify-yaml.mjs candidates/flash-plan-probe-v1.patch.yml
      ✓ 顶层是数组
      ✖ 含 v1/v2/v3 三个预设行（实际: 无）     ← 假失败

候选文件本来就不该含我们的预设行，这个断言只对"profile 安装目标"成立。现在只有文件里已经出现本仓库预设行、或路径形如 `profiles/` 时才硬断言，其余打印"非安装目标，跳过"。修完 4 个候选全部通过，而安装目标仍然严格（拿线上 profile 补丁验证：仍要求三行齐全）。

### P3 · 精简预设缺三个官方插件（不修，但要写明）

对比官方 `preset-ptc`（33 项）：我们缺 `time-context`、`tool-schedule`、`tool-plugin-market`，多 `tool-subagent-codex`、`tool-subagent-claude-code`、`tool-ralph`。

影响：提示词里没有当前日期、没有调度工具、不能从对话里装插件。这是刻意的裁剪，但此前**任何文档都没写**——用户碰到"模型不知道今天几号"会以为是 bug。已在 README 新增「已知偏差（相对官方 preset-ptc）」表。
