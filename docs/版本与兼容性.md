## 注意事项

1. **不要再写 `.../list-agents` 子路径。** DSH 0.2.2-rc.1 把 `list_agents` 并进 `@deepseek-ai/dsh-tool-subagent-control` 主插件，`exports` 只剩 `"."`；预设里再出现这一行会 import 失败，**整份预设**被判 broken，GUI 卡片显示「加载失败」。报错只给行 id 与插件名（`tool-subagent-list-agents (@deepseek-ai/...): never started`），不直接指向子路径，容易误判成 DSH 版本问题。
2. **补丁层只有两个预设行：`flash-lean-ptc-v3`（13 条，默认）与 `flash-lean-ptc-v3-balance`（3 条），id 从 0.2.9 起固定不变。** 其余发布过的历史 id 都进 `presets/legacy-preset-map.json` 的别名表，由 `flash-presets-alias` 那一行的运行时别名层在**解析失败时**映射到 `flash-lean-ptc-v3`，不改写任何会话文件。其中 `flash-lean-ptc-v1` / `-v2` 规则与 v3 不同（标 `rulesDiffer`，首次命中打印警告）且不随包发行，要原规则就在自己的 profile 补丁里加行。会话里的 id 不要改写 —— DSH 会话日志是多帧 zstd，整文件重写会丢事件流。
3. **装完必须重启宿主**（desktop）；`web` 刷新页面即可。补丁层只在启动时合成，热装不会生效。`headless` 下预设停在 pending，重启也不会激活；`acp` 未验证（见上表）。
4. **自检命令**：`dsh --profile web --dump-config | grep -c 'id: preset-'` 期望 6（内置 4 条 + 本包 2 条；若你自己在 profile 层加了兼容行，按行数递增）；`grep -c 'persistent-in-memory'` 期望 1；`grep -c 'plan-mode-ui'` 期望 1。
5. 预设只声明插件行、不带插件包。profile 缺对应插件时这些行会失效，安装器不会补依赖。

## 模拟安装回归

```bash
SIM=/tmp/dshsim
mkdir -p $SIM/profiles/web && echo '[]' > $SIM/profiles/web/cordis.patch.yml
DSH_HOME=$SIM bash scripts/install.sh --profile web
DSH_HOME=$SIM node scripts/verify-presets.mjs
dsh --profile web --patch $SIM/profiles/web/cordis.patch.yml --dump-config | grep 'id: preset-flash-lean-ptc'
DSH_HOME=$SIM bash scripts/install.sh --profile web --uninstall
```

断言点：

- 托管块的 BEGIN 与 END 各一份，两个预设行齐全（v3 / balance）。
- `--dump-config` 中 `preset-flash-lean-ptc-v3` 与 `preset-flash-lean-ptc-v3-balance` 两条都在（`v1` / `v2` 不随包发行；0.2.7–0.2.8 的 `-lite` 由 alias 层解析）。
- 重复安装不产生第二份托管块。
- 卸载后托管块与预设行计数归零。
- `verify-presets.mjs` 逐个预设核对 order、规则条数、压缩阈值、保留预算、裁剪阈值、PTC 与 tool-workflow。

## 升级路径

0.2.0 到 0.2.1 是纯追加：新增 v3 与多预设支持，v1 与 v2 的定义、order 均未改动。已安装的 profile 重新安装一次即可获得 v3。

0.2.9 起：13 条版的 id 固定为 `flash-lean-ptc-v3`、3 条版是 `flash-lean-ptc-v3-balance`，**不再随版本改名**（DSH 把 preset id 写进会话日志，改名等于让旧会话报 `agent-preset/not-found`）。发行包只有这两张卡；`flash-lean` / `flash-lean-ptc` / 0.2.7–0.2.8 的 `-lite` 走 alias 层解析到 v3（不改写任何会话文件），v1/v2 也不随包发行（规则不同），但**同样在别名表里**（`rulesDiffer: true`，加载时打一条警告）——0.2.8 能打开的会话，0.2.9 必须还能打开。要原规则就在自己的 profile 补丁里加行。个人实验 id 请用 `DSH_FLASH_PRESETS_ALIAS_EXTRA` 指向自己的映射文件。

## 一张插件卡、两个预设（0.2.6 起）

DSH 的一张插件卡对应一个 npm 包，卡里列出的组件就是该包补丁层的内容。0.2.6 起的补丁层不插入第三个兼容卡；0.3.4 起插件页上本包有 4 个组件（两个预设 + 一行 `flash-presets` + Bash 工具 `fl-bash`），此前是 6 个：

| 补丁层内容 | 说明 | 形式 |
|---|---|---|
| `preset-flash-lean-ptc-v3`、`preset-flash-lean-ptc-v3-balance` | 两个预设，前者默认 | `cordis.patch.yml` 里的两条 `insert` |
| `flash-presets`（0.3.4 起） | 运行时功能的唯一一行：run_code 优化 A、计划模式宿主、历史 preset id 兼容、交付门（默认关）。行本身 inject 为空，四个功能作为子插件各按自己的 inject 启动（别名层只要 `agentPresets`，桌面端照常） | 同一份补丁里的一条 `insert`，`name: 'dsh-flash-presets'`（→ `lib/bundle.js`） |
| `fl-bash`（0.3.4 起） | Windows x64 的 Bash 工具 `fl_bash`，插件页上单独一个组件，默认关；`name: dsh-flash-presets/fl-bash`（`lib/fl-bash-row.js`），实现 `lib/fl-bash.js` 与 `vendor/win32-x64/flash-sh.exe` 随包发行（由 `plugins/flash-sh` 同步），非 Windows x64 上这一行只写一行 info | `cordis.patch.yml` 里的 `insert` |
| `flash-presets-core` / `plan-mode-ui` / `flash-presets-alias` / `delivery-gate`（0.3.2 及以前） | 上面四个功能各占一行 | 0.3.4 起不再插入；按这些 id 写的用户覆盖由 `lib/row-overrides.js` 读回生效 |
| `ptc-runtime: persistent-in-memory` | 常驻 PTC 运行时 | 同一份补丁的顶层配置覆盖（不是 `insert`） |

历史 id 一律进 `presets/legacy-preset-map.json` 的别名表，由 `lib/alias-plugin.js`（0.2.9–0.3.2 是 `flash-presets-alias` 行，0.3.4 起是 `flash-presets` 行的子插件；都只 inject `agentPresets`）在运行时解析到 `flash-lean-ptc-v3`，只在该解析失败时介入、不改写任何会话文件。规则不同的 `flash-lean-ptc-v1` / `-v2` 也映射，但标 `rulesDiffer: true`、首次命中打印警告；它们不随包发行。规则相同的 `flash-lean`、`flash-lean-ptc`、0.2.7–0.2.8 的 `flash-lean-ptc-v3-lite` 同样在表里。0.2.8 时期的口径是「规则不同就不映射、只在 `presets/compat-exceptions.json` 里留 reason + fallback」，第五轮审计判定那本身是个回归（0.2.8 打得开的会话 0.2.9 打不开），已改回全部映射。例外表因此清空，机制保留。
