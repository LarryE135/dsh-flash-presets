## DSH 0.2.2-rc.1 的接口变更（issue #19）

`@deepseek-ai/dsh-tool-subagent-control` 的 exports 对比：

| 版本 | exports | root 注册的工具 |
|---|---|---|
| 0.2.1-rc.5 | `.`, `./list-agents`, `./src/*`, `./package.json`, `./locale/*.json`, `./list-agents/locale/*.json` | `send_message` / `interrupt_agent` |
| 0.2.2-rc.1 | `.`, `./src/*`, `./package.json`, `./locale/*.json` | `list_agents` / `send_message` / `interrupt_agent` |

`./list-agents` 子路径被删除后，预设里仍指向它的 `tool-subagent-list-agents` 行无法启动 fiber，四个预设全部报 `agent-preset/invalid: ... never started`，新建会话失败。把它改指 root 也不行：`dsh-tools` 的 `NamedEntries` 会做工具名唯一性校验，同一个包加载两次报 `already registered in this scope`。

修复是删掉整行（4 个源预设 + 合成产物共 8 处，另清理归档候选 1 处），由 root 一行提供全部三个工具。`compose-bundle-patch.mjs`（唯一合成入口）和 `verify-yaml.mjs`（逐预设 + 合成产物）都会拦住回归；`doctor.mjs --fix` 负责清理已安装用户 profile 里的旧托管块。

取舍：0.2.1 系列的 root 没有 `list_agents`，删行后该版少这个工具。要在两个 DSH 版本上同时保留它，得按运行时版本分发两套预设（或用 `!!js` 条件行），但那会让安装器的 `!!js` 平台解析链复杂化且未经实测；本版不做双版本分发。需要该工具的 0.2.1 用户留在 0.2.5。

验证口径（无需起服务）：

```bash
node scripts/compose-bundle-patch.mjs --check
node scripts/verify-yaml.mjs
dsh --profile web --dump-config | grep -c "tool-subagent-list-agents"   # 0
dsh --profile web --dump-config | grep -c "id: tool-subagent-control"   # 每个预设 1 次
```

## 模拟安装回归

```bash
SIM=/tmp/dshsim
mkdir -p $SIM/profiles/web && echo '[]' > $SIM/profiles/web/cordis.patch.yml
DSH_HOME=$SIM bash scripts/install.sh --profile web
DSH_HOME=$SIM node scripts/verify-presets.mjs
dsh --profile headless --patch $SIM/profiles/web/cordis.patch.yml --dump-config | grep preset-flash-lean-ptc
DSH_HOME=$SIM bash scripts/install.sh --profile web --uninstall
```

断言点：

- 托管块的 BEGIN 与 END 各一份，三个预设行齐全。
- `--dump-config` 中 `preset-flash-lean-ptc-v1`、`v2`、`v3` 全部出现。
- 重复安装不产生第二份托管块。
- 卸载后托管块与预设行计数归零。
- `verify-presets.mjs` 逐个预设核对 order、规则条数、压缩阈值、保留预算、裁剪阈值、PTC 与 tool-workflow。

## 一张卡三个组件（0.2.6 起）

DSH 的一张插件卡对应一个 npm 包，卡里列出的组件就是该包补丁层的插入行。预设与计划模式现在同属一个包，装一次、三个组件都在。

| 包 | 卡片上的组件 | 提供形式 |
|---|---|---|
| `dsh-flash-presets` | `preset-flash-lean-ptc-v3`、`preset-flash-lean-ptc-v3-max`、`preset-flash-lean-ptc-v3-lite`、`preset-flash-lean-ptc-v3-none` | 补丁层 `cordis.patch.yml` 里的两条 insert |
| 同上 | `plan-mode-ui` | 包根 `main`（`lib/index.js`）与 `dsh.client`（`lib/client.js`） |

一条命令装上即可：

```bash
dsh plugin --profile web add dsh-flash-presets@0.2.8
dsh plugin --profile web add dsh-plan-mode-ui@0.7.0
```

从合并包迁移时有三点会直接导致新建会话失败，本机各踩过一次：

1. 不要同时保留手写的预设行。预设 id 由补丁层里的行定义，profile 里再写一遍 `preset-flash-lean-ptc-v3` 就是重复注册，预设层判 invalid，新建会话报 `agent-preset/invalid`。清掉旧的托管块和手写行，只留 `agent-preset-registry`。
2. `selectedDefault` 必须指向真实存在的预设 id。删预设行时漏改这个字段，新建会话报 `Unknown agent preset: <id>`。它记的是预设 id（`flash-lean-ptc-v3`），不是行 id（`preset-flash-lean-ptc-v3`）。
3. 桌面端、headless、acp 只在启动时读补丁层，装完要完全退出再启动；web profile 刷新页面即可。

验证命令与期望一致的三项：

```bash
dsh --profile web --dump-config | grep -c 'id: preset-'    # 内置 4 条 + 本包 2 条 = 6
dsh --profile web --dump-config | grep -c 'persistent-in-memory'   # 1
dsh --profile web --dump-config | grep -c 'plan-mode-ui'   # 3
```

回退到合并包：先 `dsh plugin remove dsh-plan-mode-ui`，再装 0.2.5 的 `dsh-flash-presets`。合并版已停止维护，仅作回退用途。
