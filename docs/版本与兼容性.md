# 版本与兼容性

## 版本对应

| dsh-flash-presets | DSH | 说明 |
|---|---|---|
| 0.2.3（未发布，PR 合入 main） | 0.2.1-rc.2 | engines.dsh 兼容门、plan-mode 漂移检查、自检插件、bench 管线；发布后转正 |
| 0.2.2 | 0.2.1-rc.2 | 当前发布版本（npm 最新）；v3 主版本 |
| 0.2.1 | 0.2.1-rc.2 | v3（lean-v3）定稿，安装器与校验器支持三预设 |
| 0.2.0 | 0.2.0 | 声明为组合包，发布 v2 |
| 0.1.0 | 0.1.7-rc.1 至 0.2.0 | 首个发布，v1 |

预设机制自 DSH 0.1.7-rc.1 起改为插件行加用户补丁层。本仓库 0.2.x 全部基于该机制，与 0.2.1 对齐。0.2.3（未发布）起 package.json 声明 `engines.dsh: ">=0.1.7-rc.1 <0.3.0"`：DSH 插件管理器在安装与激活时校验该范围，不满足即拒绝；0.1.7 以前只有 v1 的目录式回退，0.3 起视为未知破坏面。

## 兼容性

| 项目 | 状态 | 依据 |
|---|---|---|
| DSH 0.2.1-rc.2 | 通过 | 模拟安装后 `--dump-config` 合成出 v1、v2、v3 与自检行，`--check` 一致；plan-mode section 与上游逐词一致（漂移检查） |
| DSH 0.1.7 至 0.2.0 | 通过 | 插件行机制未变，安装器逻辑未变；自检插件在无 agentPresets 服务时降级为静态行检查 |
| DSH 0.1.7 以前 | 部分 | 仅 v1 有 `presets/legacy-0.1.5/` 目录式回退 |
| 0.3.0 及以上 | 拒绝 | `engines.dsh <0.3.0`；确需使用走 exact-version 豁免（自担风险） |
| web profile | 通过 | live reload，刷新即生效 |
| desktop、headless、acp | 通过 | 需重启，补丁层只在启动时读取 |
| Windows PowerShell | 通过 | `scripts/install.ps1`，与 sh 版共用合并器 |
| Linux、WSL | 通过 | `scripts/install.sh` |
| macOS | 未验证 | 脚本按 bash 3.2 兼容写，变量后接非 ASCII 字符时用 `${var}` |
| 第三方 YAML 解析器 | 受限 | 补丁含 `!!js` 标签，非 DSH 解析器会报 unknown tag |

## 模拟安装回归

```bash
SIM=/tmp/dshsim
mkdir -p $SIM/profiles/web && echo '[]' > $SIM/profiles/web/cordis.patch.yml
DSH_HOME=$SIM bash scripts/install.sh --profile web
DSH_HOME=$SIM node scripts/verify-presets.mjs
dsh --profile headless --patch $SIM/profiles/web/cordis.patch.yml --dump-config | grep preset-flash-lean-ptc
DSH_HOME=$SIM bash scripts/install.sh --profile web --uninstall
```

断言点：

- 托管块的 BEGIN 与 END 各一份，三个预设行齐全。
- `--dump-config` 中 `preset-flash-lean-ptc-v1`、`v2`、`v3` 全部出现。
- 重复安装不产生第二份托管块。
- 卸载后托管块与预设行计数归零。
- `verify-presets.mjs` 逐个预设核对 order、规则条数、压缩阈值、保留预算、裁剪阈值、PTC 与 tool-workflow。

bundle 形态（`dsh plugin add`）额外包含宿主自检行 `flash-presets-selfcheck`（`lib/selfcheck.mjs`），CI 断言其进入组合且不阻断启动；脚本渠道（install.sh/ps1 的托管块）不含该行——那是 0.1.7 前的安装路径，没有 bundle 包目录可解析模块。

## 升级路径

0.2.2 到 0.2.3（未发布）是纯追加与修正：预设定义（order、规则数、压缩阈值）未变，新增宿主自检行、engines 门与校验脚本；plan-mode section 措辞对齐 0.2.1-rc.2 上游（行为等价，只是政策文案同步）。0.2.0 到 0.2.1 是纯追加：新增 v3 与多预设支持，v1 与 v2 的定义、order 均未改动。已安装的 profile 重新安装一次即可获得新版本。

## 安装渠道验证（2026-10-20 / 2026-11）

在临时 `DSH_HOME` 下用插件管理器实装过两条渠道，均成功：

| 渠道 | 命令 | 结果 |
|---|---|---|
| 本地目录 | `dsh plugin --profile web add file:/path/to/dsh-flash-presets` | 写入 `dsh.profile.bundles`，`--dump-config` 见 v1/v2/v3 |
| GitHub | `dsh plugin --profile web add github:LarryE135/dsh-flash-presets#v0.2.2` | 同上；不带 `#tag` 时跟 main（移动目标，勿用于可复现安装） |
| npm 包名 | `dsh plugin --profile web add dsh-flash-presets@0.2.2` | 0.2.2 起可用；写死版本可复现 |

GUI 的「插件 → 添加插件」等价于这些渠道的命令行形态：填裸包名、GitHub 地址或本地目录都可以。注意 GUI 在 HMR profile（web）下对已装包报 `already-installed`，更新需先移除再安装。

npm 通道已于 2026-10-21 打通（0.2.2 起），`files` 字段包含 `scripts/`、`lib/`、`bench/` 与 `docs/`，因此从 npm 安装同样拿得到手动安装脚本、自检插件与评测管线。
