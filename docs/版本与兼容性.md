## 注意事项

1. **不要再写 `.../list-agents` 子路径。** DSH 0.2.2-rc.1 把 `list_agents` 并进 `@deepseek-ai/dsh-tool-subagent-control` 主插件，`exports` 只剩 `"."`；预设里再出现这一行会 import 失败，**整份预设**被判 broken，GUI 卡片显示「加载失败」。报错只给行 id 与插件名（`tool-subagent-list-agents (@deepseek-ai/...): never started`），不直接指向子路径，容易误判成 DSH 版本问题。
2. **补丁层只有两个预设行：`flash-lean-ptc-v3`（13 条，默认）与 `flash-lean-ptc-v3-balance`（3 条），id 从 0.2.9 起固定不变。** `flash-lean-ptc-v1` / `-v2` 不随包发行（规则与 v3 不同，不映射，只在 `presets/compat-exceptions.json` 登记 reason + fallback），要就在自己的 profile 补丁里加行；`flash-lean` / `flash-lean-ptc` / 0.2.7–0.2.8 的 `-lite` 由运行时 alias 层（`presets/legacy-preset-map.json`）在解析失败时映射到 v3，不改写任何会话文件。会话里的 id 不要改写——DSH 会话日志是多帧 zstd，整文件重写会丢事件流。`selectedDefault` 建议写 `flash-lean-ptc-v3`。
3. **装完必须重启宿主**（desktop）；`web` 刷新页面即可。补丁层只在启动时合成，热装不会生效。`headless` 下预设停在 pending，重启也不会激活；`acp` 未验证（见上表）。
4. **自检命令**：`dsh --profile web --dump-config | grep -c 'id: preset-'` 期望 6（内置 4 条 + 本包 2 条；若你自己在 profile 层加了兼容行，按行数递增）；`grep -c 'persistent-in-memory'` 期望 1；`grep -c 'plan-mode-ui'` 期望 1。
5. 预设只声明插件行、不带插件包。profile 缺对应插件时这些行会失效，安装器不会补依赖。

## 模拟安装回归

```bash
SIM=/tmp/dshsim
mkdir -p $SIM/profiles/web && echo '[]' > $SIM/profiles/web/cordis.patch.yml
DSH_HOME=$SIM bash scripts/install.sh --profile web
DSH_HOME=$SIM node scripts/verify-presets.mjs
dsh --profile web --patch $SIM/profiles/web/cordis.patch.yml --dump-config | grep 'id: preset-flash-lean-ptc'
DSH_HOME=$SIM bash scripts/install.sh --profile web --uninstall
```

断言点：

- 托管块的 BEGIN 与 END 各一份，两个预设行齐全（v3 / balance）。
- `--dump-config` 中 `preset-flash-lean-ptc-v3` 与 `preset-flash-lean-ptc-v3-balance` 两条都在（`v1` / `v2` 不随包发行；0.2.7–0.2.8 的 `-lite` 由 alias 层解析）。
- 重复安装不产生第二份托管块。
- 卸载后托管块与预设行计数归零。
- `verify-presets.mjs` 逐个预设核对 order、规则条数、压缩阈值、保留预算、裁剪阈值、PTC 与 tool-workflow。

## 升级路径

0.2.0 到 0.2.1 是纯追加：新增 v3 与多预设支持，v1 与 v2 的定义、order 均未改动。已安装的 profile 重新安装一次即可获得 v3。

0.2.9 起：13 条版的 id 固定为 `flash-lean-ptc-v3`、3 条版是 `flash-lean-ptc-v3-balance`，**不再随版本改名**（DSH 把 preset id 写进会话日志，改名等于让旧会话报 `agent-preset/not-found`）。发行包只有这两张卡；`flash-lean` / `flash-lean-ptc` / 0.2.7–0.2.8 的 `-lite` 走 alias 层解析到 v3（不改写任何会话文件），v1/v2 既不映射也不随包发行（规则不同），需要时在自己的 profile 补丁里加行。个人实验 id 请用 `DSH_FLASH_PRESETS_ALIAS_EXTRA` 指向自己的映射文件。

## 安装渠道验证（2026-10-20）

在临时 `DSH_HOME` 下用插件管理器实装过两条渠道（本地目录、GitHub），均成功；npm 渠道的情况见下表末行。

| 渠道 | 命令 | 结果 |
|---|---|---|
| 本地目录 | `dsh plugin --profile web add file:/path/to/dsh-flash-presets` | 写入 `dsh.profile.bundles`，`--dump-config` 见预设行（当时包里还是 v1/v2/v3 三条，0.2.6 起只剩 lite 与 balance） |
| GitHub | `dsh plugin --profile web add github:LarryE135/dsh-flash-presets` | 同上，pnpm 解析 git 依赖耗时约 3 s；要可复现请带 tag（`…#v<版本>`），不带 tag 装的是默认分支 |
| npm 包名 | `dsh plugin --profile web add dsh-flash-presets` | 0.2.2 起可用，但解析的是 `latest`：npm 上最新仍是 0.2.5，它在 DSH 0.2.2-rc.1 上无法新建会话（#19），**现在不要用这条**。在 npm 上有可用版本之前，请用 `github:LarryE135/dsh-flash-presets#<tag>` 安装（tag 见 README 与 Release） |

GUI 的「插件 → 添加插件」等价于这些渠道的命令行形态：填裸包名、GitHub 地址或本地目录都可以。

npm 通道已于 2026-10-21 打通（0.2.2 起）。`files` 是白名单，不是整目录发布：手动安装脚本（`scripts/install.sh` / `scripts/install.ps1`）与 `scripts/doctor.mjs` 等逐个列出，所以从 npm 或插件管理器安装同样拿得到它们。随包文件的完整清单以 `package.json` 的 `files` 字段为准。

`docs/` 从 0.2.6 起只发白名单里的几篇（`CHANGELOG.md`、`版本与兼容性.md`、两份技术文档、`实测证据.md`、`预设-id-契约与升级.md`）：审计记录、实验记录、`PUBLISHING.md` 等内部过程文档不再进入 npm 包；`scripts/` 里的发布脚本（`publish.sh` / `publish.ps1` / `npm-downloads-badge.mjs` / `lint-allowlist.json`）与仓库内维护脚本（如 `align-presets.sh`）也排除了。

包体大小与文件数请现查，不要照抄文档里的数字：已发布的版本用 `npm view dsh-flash-presets dist.fileCount dist.unpackedSize`，下一个版本发布前用 `npm pack --dry-run` 核对。tarball 不含 `dist/`，也不需要构建步骤。

## 一张插件卡、两个预设（0.2.6 起）

DSH 的一张插件卡对应一个 npm 包，卡里列出的组件就是该包补丁层的内容。0.2.6 起的补丁层**只插入两个预设行和一行计划模式组件**，没有第三个兼容卡：

| 补丁层内容 | 说明 | 形式 |
|---|---|---|
| `preset-flash-lean-ptc-v3`、`preset-flash-lean-ptc-v3-balance` | 两个预设，前者默认 | `cordis.patch.yml` 里的两条 `insert` |
| `plan-mode-ui` | 计划模式组件，宿主半边与浏览器半边都来自本包 | 同一份补丁里的一条 `insert` |
| `ptc-runtime: persistent-in-memory` | 常驻 PTC 运行时 | 同一份补丁的顶层配置覆盖（不是 `insert`） |

历史 id 分两类处理：**规则相同的**（`flash-lean`、`flash-lean-ptc`、0.2.7–0.2.8 的 `flash-lean-ptc-v3-lite`）进 `presets/legacy-preset-map.json` 的别名表，由 `lib/preset-alias.js` 在运行时解析到 `flash-lean-ptc-v3`，只在该解析失败时介入、不改写任何会话文件；**规则不同的**（`flash-lean-ptc-v1`、`-v2`）既不随包发行也不映射，改为在 `presets/compat-exceptions.json` 里留 reason + fallback，谁需要谁在自己的 profile 补丁里加行。

装一次就够：安装命令、重启要求与卸载方式见 README 的「安装」一节（npm 上的 0.2.5 不可用，具体版本号以 README 与 Release 上的 tag 为准）。
