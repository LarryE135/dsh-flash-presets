# 办公基准 · 发布前人工复核清单

自动守卫（`scripts/guard-bench-leak.mjs`）只能拦"形状可识别"的泄漏。
下面三项**自动检测不了**，必须人眼过一遍；跑 `npm run checklist:bench` 会把证据收集好，你只需要逐项确认。

## ① 本次改动里没有"粘进去的真值"

守卫能判表格文件、命名、历史 blob，**判不了散文里的几行 CSV**。

怎么做：

```bash
git diff --cached --stat                    # 先看这次动了哪些文件
git diff --cached -- benchmarks/ README.md  # 再逐段看新增的文本
```

重点看：新增的 fenced code block、表格、注释里有没有"整行整行的逗号分隔数据"、
有没有出现某题真值的完整行（尤其 `source_ref` 那种长串）。

判据：**新增文本里不出现任何一题交付数据的完整行**。示例行最多保留 1 行且明显是编的。

## ② 没有用 base64 / 图片 / 压缩包夹带

守卫只看文本和已知命名，不解析二进制载荷。

怎么做：

```bash
grep -rnE "base64,|data:image/" benchmarks/ | head
git ls-files benchmarks/ | grep -Ei "\.(zip|png|jpe?g|pdf|gif|webp|woff2?|xlsx?)$"
```

判据（两段）：

- **`inputs/` 之外**：不允许任何二进制（zip/png/xlsx/pdf…）。
- **`inputs/` 之内**：允许，但必须是本题 `input_manifest.json` 登记过的输入件；未登记一律失败。

### ②' 图片 / 扫描件类输入（必须人眼确认）

目前只有 **O08** 有 9 张 PNG：`base-v1/O08/inputs/pages/page-01…09.png`，这是题目设计
（扫描小票共 9 页，要求做 OCR 与流水核验）。它们是**原材料**，不是夹带。

但这类输入是自动检查的盲区：一张图里若画着答案表，任何字节扫描都判不出来。所以每次发布要人眼过一遍：

1. 跑 `npm run checklist:bench`，它会把每张图逐条列出来；
2. 确认内容是"要处理的小票/扫描件"，**不是**"答案表格的截图"；
3. 确认新增图片已登记进 `input_manifest.json`（否则 `npm run bench:office` 会报"输入未登记"）。

## ③ 私有库不能从公开侧直达

守卫会拦 submodule 与命名，但拦不了"文档里贴了一个能下载的链接"。

怎么做：

```bash
git ls-files | grep -c "^\.gitmodules$"          # 必须 0
grep -rn "dsh-office-bench-private" --include=*.md . | grep -E "blob/|raw/|tree/|releases/"
gh repo view LarryE135/dsh-office-bench-private --json isPrivate
```

判据：
- 没有 `.gitmodules`；
- 文档里可以**提**私有仓库名（供维护者对照），但**不许出现指向 blob/raw/tree/releases 的可下载链接**；
- `isPrivate` 必须为 `true`。

## 三项之外的常规门禁（自动，必过）

```bash
npm run verify          # 含防泄漏守卫 + 预设审计
npm run bench:office    # 13 题结构/完整性/表头一致
```
