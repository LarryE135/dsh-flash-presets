# v5.5 评分标准

适用于 P01–P05。依据《执行与评分说明.md》、score.py 和 grade_batch.py 整理。此版不使用六维加权质量分。

## 任务分

按规定文件与主键定位记录，逐一比较私有真值中要求的全部单元格，包括主键字段。

任务分 = 匹配的期望单元格数 / 全部期望单元格数 × 100。

同一任务内所有要求表的期望单元格合并计数。缺失文件、不可读文件或缺失记录，对应期望单元格保留在分母，匹配数为 0。额外记录不增加分母，但会触发主键集合异常。

比较采用 CSV 解析后的字符串完全相等。评分器不额外做空白裁剪、标点替换、Unicode 规范化或数字格式等价转换。例如 `1` 与 `1.0` 不相等。只有题面明确要求的业务规范化才属于作答步骤。行顺序不限；表头顺序必须与契约一致。

重复主键会使 exact 失败；当前实现以最后出现的同键记录参与单元格分计算，因此单元格得分不能替代结构有效性。

## exact：全部精确通过

任务 exact 要求匹配单元格数等于总单元格数，并且没有问题记录。以下情况会使 exact=false：

- 缺失或不可读文件。
- 表头名称或顺序变化。
- 重复主键、缺失或额外主键。
- 任一要求单元格不匹配。
- deliverables 中存在额外文件，包括子目录中的额外文件。

因此任务分即使为 100，仍可能因表头顺序、重复记录或额外交付而 exact=false。单轮 exact 需要五题均 exact；全部运行 exact 需要每个纳入的运行均通过。

此 exact 是交付内容与结构判定。模型、预设、会话独立性和日志完整性需另行核验，评分器不会凭此标志证明它们。

## 五任务等权与重复

单轮总分 = (P01分 + P02分 + P03分 + P04分 + P05分) / 5。

模式质量均值 = 已纳入各轮总分的算术平均。五题之间等权，不按任务数据量加权；不要用全部任务匹配单元格直接合池代替这一公式。

批量实现会对已发现的每个运行目录评分五题，缺失任务按对应缺失文件计分；但它不会自动发现完全缺失的运行目录。报告必须对照预定运行清单列出缺失轮，不能把未发现的轮次隐去后声称完成全部计划。原说明建议每预设五轮独立重复。

显示值保留四位小数；应同时保留匹配单元格数、分母及 exact，避免四舍五入掩盖差异。模式报告附逐轮分、逐题分及离散程度。

## 题面歧义与历史结果

现有资料说明记录了题面书写歧义造成的有限文本差异。这不等于原始评分器自动接受不同写法。

如需接受等价写法，应保存争议字段与依据，冻结并对所有模式一致应用同一解释，分别报告“原始严格匹配”和“经统一歧义裁定”的结果。未完成统一复评时，不将历史交付推定为全 exact。本说明不修改真值或追认历史分数。
