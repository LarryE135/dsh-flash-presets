# P0/P1 验收清单模板

原则：**P0 是判定项（任一失败即整体失败），P1 是目标区间（不达标不算失败）**。
41 条平铺清单会让实现者把预算全花在配角断言上（实测 603k / 60 分钟未收敛）；分层后 250k / 22 分钟收工。

## P0 — 必须过（建议 10–14 条，全部可脚本判定）

| # | 断言 | 判定方式 |
|---|---|---|
| P0-1 | 拖拽向右 200 px → 方位角变化 1.0–1.4 rad，符号符合 C2 | 读诊断对象 |
| P0-2 | 拖拽向左 200 px → 反向，幅度相同 | 读诊断对象 |
| P0-3 | 滚轮 −200 → 半径减少；+200 → 半径增加 | 读诊断对象 |
| P0-4 | 纵向拖拽改变极角，且被夹紧不穿地 | 读诊断对象 |
| P0-5 | 暂停：1.2 s 内两帧像素差 < 0.1%，仿真时间不增长 | 截图比对 + 诊断 |
| P0-6 | 暂停中相机仍可拖动；恢复后动画继续 | 读诊断对象 |
| P0-7 | 主体尺寸/包围盒落在约定区间 | 读诊断对象 |
| P0-8 | 投影正确：fov 语义、默认构图主体完整可见 | 读诊断 + 首帧截图 |
| P0-9 | 时间单位正确（用一条可观测的物理过程验证，如落体 10–25 s） | 读诊断 |
| P0-10 | 色彩空间/色调映射符合 C8 | 读诊断对象 |
| P0-11 | 无控制台错误、无 WebGL 报错 | 页面事件 |
| P0-12 | 暴露只读诊断字段（见 C10） | 代码检查 |

## P1 — 目标区间（建议 ≤5 条，写成数字区间）

| # | 目标 | 说明 |
|---|---|---|
| P1-1 | 主色占比 8–12% | 太稀太满都扣分；注意与需求文案是否冲突 |
| P1-2 | RMS 对比度 ≥ 45 | 多数首版停在 22–30，偏低；给打光配方而非形容词 |
| P1-3 | 纯白像素占比 ≤ 0.5% | 防整屏泛白闪烁 |
| P1-4 | 主体占画面高度 55–85% | 构图 |
| P1-5 | 关键观感要素存在（如地面投影） | 用质心/轮廓判定，不靠感觉 |

## 实现者侧要求

- 交付单文件 + 一份逐条实测报告（每行：编号 / 实测值 / PASS 或 FAIL）；**FAIL 必须如实写**。
- 每改一版就用工具量一次，不要写完再测。
- 预算写死（时间 + token），到点就交：宁可 P1 留白，也要保证 P0 全过。
